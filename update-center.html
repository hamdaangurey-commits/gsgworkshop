How every update is approved

1 · Prepare

A proposed code change is committed to a separate GitHub branch. The live main branch stays untouched.

2 · Test

GitHub Actions checks JavaScript syntax and confirms the existing finance-data key is still present. Netlify may provide a separate preview if deploy previews are enabled.

3 · Review

Open Files changed, inspect the preview and make a finance-data backup. A green check alone is not permission to release.

4 · ACCEPT

Only after you explicitly approve the exact change should you merge that pull request. Never share access tokens or passwords in chat.

5 · Deploy and verify

If Netlify is connected to this GitHub repository with production deploys from main, the merge may trigger production deployment. Verify the live site afterwards.

6 · Roll back if needed

Use Netlify's Deploys history to publish a previously successful deploy. This restores website files, not finance data stored on a phone. Restore finance data only from a verified JSON backup.

Finance data protection

Your finance data is saved in this browser under hamdan_os_v1. This backup is separate from GitHub and Netlify. It downloads a JSON file and does not upload your transactions anywhere.

Important: importing a backup into HAMDAN PERSONAL OS replaces the current browser data. Keep the newest backup safe and never import an unfamiliar file.
